The short version

What changed after measuring

Running Whisper locally on this hardware is not a privacy compromise that costs speed. It is faster than the paid cloud product it replaces, free forever, and the recording never leaves the machine. That was not the expected result.

Three findings changed the plan. The recommended starting point (whisper.cpp) is the worst option on this specific GPU. The library everyone says crashes on RTX 50-series Measured does not crash — that advice is a year stale. And the real blocker was never Blackwell at all; it was a Windows DLL path, which took four minutes to find and one function to fix.

Measured on this box

faster-whisper 1.2 · CTranslate2 4.8.2 · large-v3-turbo · beam size 5

Ground truth was the standard 11-second JFK sample, so accuracy is checkable rather than vibes-based. Both compute types returned the reference sentence verbatim, punctuation included.

Compute type Model load First call Warm median Throughput Accuracy
int8_float16 2.09s 0.55s 0.36s 30.8× Exact match
float16 1.18s 0.37s 0.37s 29.9× Exact match

The two are within noise of each other once warm, so int8_float16 buys nothing here and float16 is the simpler default. What matters far more is the first call: an earlier run showed 20.7 seconds on the very first GPU operation of a process while CUDA built its kernels. That cost is paid once per process, not per compute type.

Design consequence for the dictation app

The model must stay resident in a long-lived tray process, and the app must fire a throwaway warmup transcription at startup. Skip that and the first thing you dictate each session takes twenty seconds — which reads as a broken app, not a cold cache.

Against the thing it replaces

Wispr Flow’s published figure is roughly 700ms end-to-end, achieved by streaming to their cloud. Local inference on this GPU beats it while never touching the network.

Claims audit

Advice received before this research, checked line by line

The prior guidance was directionally sound and specifically wrong in two places that would have cost real time. Keeping the score honest:

ClaimVerdictWhat is actually true
Local-only, because there is no BAA covering this audio Verified Correct and non-negotiable. Drove every other decision here.
faster-whisper is much faster than reference Whisper Verified Roughly 4× via CTranslate2. Confirmed at 30× realtime here.
Convert to 16kHz mono WAV first Verified Still required by whisper.cpp, good hygiene everywhere.
whisper.cpp is the simplest thing to get running Refuted Backwards on this GPU. Prebuilt Windows CUDA binaries target CUDA 12.4, which predates Blackwell — expect no kernel image available. Building from source needs cmake, MSVC and CUDA 12.8, none of which are installed. The “simplest” option is the hardest one here.
faster-whisper gives easier speaker segmentation Refuted faster-whisper does not diarize at all. It emits word-level timestamps and zero speaker labels. Telling two people apart needs WhisperX plus pyannote bolted on. This is the claim that would have cost the most time.
Use large-v3 for accuracy Refuted Superseded by large-v3-turbo: near-equal accuracy, ~7–8× faster, ~6GB VRAM instead of ~10GB. large-v3 also has multiple independent reports of worse hallucination looping than v2 — bad news on a 90-minute file.
int8 crashes on RTX 50-series, force float16 Refuted Measured int8_float16 ran clean at 30.8× realtime with an exact-match transcript. The crash was real in CTranslate2 below 4.7.0; 4.8.2 carries the fix. Widely repeated, now stale.

Two omissions that matter more than any correction

  • Set condition_on_previous_text=False. This is the documented fix for long-audio repetition cascades. Left at its default of True, one bad window poisons every window after it — precisely the failure mode a 90-minute recording invites.
  • Do not denoise before transcribing. A March 2026 paper found speech enhancement consistently raised word error rate for Whisper against raw noisy audio. The instinct to clean up the audio first actively hurts. Unverified for loudness normalization, which nobody has benchmarked either way.

The Blackwell trap

Four minutes of confusion, one function to fix

Every research thread predicted a Blackwell/sm_120 disaster. The actual failure had nothing to do with the GPU architecture: 

ctranslate2: 4.8.2
cuda_device_count: 1
FAIL float16   RuntimeError: Library cublas64_12.dll is not found or cannot be loaded

CTranslate2 saw the GPU perfectly. The pip-installed CUDA libraries (nvidia-cublas-cu12, nvidia-cudnn-cu12) unpack into site-packages, which is not on the Windows DLL search path. Documented for Linux via LD_LIBRARY_PATH; the Windows equivalent is written down nowhere.

The part that wastes an hour

os.add_dll_directory() alone is not enough. CTranslate2 delay-loads cuBLAS through the standard Windows search order, which consults PATH — not Python’s DLL directory list. You need both, and you need them before ctranslate2 is imported. 

# scripts/cuda_dlls.py — call enable() BEFORE importing ctranslate2
def enable() -> list[str]:
    base = Path(sys.prefix) / "Lib" / "site-packages" / "nvidia"
    dirs = []
    for d in sorted(base.glob("*/bin")):
        if any(d.glob("*.dll")):
            os.add_dll_directory(str(d))     # necessary
            dirs.append(str(d))
    if dirs:                                # and not sufficient
        os.environ["PATH"] = os.pathsep.join(dirs) + os.pathsep + os.environ["PATH"]
    return dirs

A second trap sat behind it: unauthenticated Hugging Face Hub calls retry with long backoff on every model load, which presented as a hang rather than an error. Setting HF_HUB_OFFLINE=1 and local_files_only=True once the model is cached removes the network from the loop entirely.

Why turbo wins despite not topping the table

faster-whisper exposes a real hotwords parameter plus initial_prompt, letting you bias decoding toward vocabulary the model keeps mangling — Pokémon set names, One Piece card terminology, medical device jargon. Parakeet is faster on paper but no shipping runtime exposes an equivalent knob. For technical dictation, biasing is worth more than the last percent of generic WER.

Adopt or build

Someone already built most of this

Handy is roughly 90% of the described app, already shipping, MIT licensed, with a signed Windows installer: push-to-talk and toggle, floating overlay, text injection with clipboard fallback, tray icon, autostart, swappable Whisper and Parakeet models, and local LLM cleanup through any OpenAI-compatible endpoint.

Recommendation: install Handy before building anything. A week of real use tells you whether the gaps — 2–5s latency, no context awareness, no command mode — actually bother you. Building custom is 2–4 Claude Code sessions, which is cheap; building blind against a hypothetical gap list is how you end up with a worse Handy.

If a custom build does happen

Do not fork Handy. It is Rust and Tauri over native ggml bindings, and this machine has neither Rust nor cmake — roughly two sessions of toolchain tax before any feature work. A purpose-built Python app matches the tools already installed and talks to faster-whisper in-process with no IPC layer.

The Ctrl+Win chord

Why the instinct was right

Settled

Wispr Flow’s own default Windows binding is Ctrl+Win, with exactly three gestures: hold to talk, double-tap to latch hands-free, tap again to end. The chord chosen from memory is the chord the real product ships.

It cannot be built the obvious way. RegisterHotKey requires a non-modifier key, so a modifier-only chord is impossible through it — this needs a WH_KEYBOARD_LL low-level hook, which pynput provides. The keyboard library, the usual suggestion, was archived in February 2026.

Four traps, in the order they will bite

  1. The Start menu. Windows opens Start when Win is pressed and released with no intervening key. Holding Ctrl first supplies that intervening key, so the chord is safe in the natural ordering — this is exactly why AutoHotkey’s built-in mask key defaults to Left Ctrl. Keep a synthetic Ctrl pulse as a fallback for the mis-ordered release; do not swallow the Win keyup, which strands the modifier in a stuck-down state.
  2. The hook must return in milliseconds. Windows silently and permanently unhooks a callback that exceeds LowLevelHooksTimeout (capped at 1000ms). No exception, no log — the hotkey simply stops working until the process restarts. Record a timestamp and return; hand everything else to a worker thread, and run a watchdog that reinstalls the hook.
  3. Ctrl+Win+D and friends. Windows already binds Ctrl+Win plus D, F4, Left/Right, Enter and C. Since the hook only observes, those still fire normally — but recording will have already started. Watch for any third key arriving while both modifiers are held, then cancel and discard the clip.
  4. Elevated windows swallow everything. A non-elevated hook receives no input while Task Manager, an admin terminal or a UAC prompt has focus. Total silence, no error. It self-heals on refocus, so ship non-elevated and accept the gap rather than running the whole tray app as administrator forever.

Gesture thresholds

Start recording on chord-down every time, for latency. Then discriminate on the gap between first release and second press: a deliberate double-tap lands under ~200ms, while two separate quick push-to-talks leave a human-perceptible gap above ~400ms. A 300–350ms latch window separates them. Because recording is already running, waiting out that window costs nothing.

Add a hard wall-clock ceiling of 60–120 seconds independent of any key-up event, plus a GetAsyncKeyState poll on a separate thread, so a key-up missed during an elevated-focus blackout cannot leave the app recording forever.

Meeting pipeline

The recording with possible PHI in it

  1. Get it off the phone by cable. Not Drive, not iCloud — that uploads unscrubbed PHI to a third party with no BAA, the exact thing being avoided. Send the original file, unconverted; a lossy re-encode measurably hurts accuracy.
  2. Check the channel count first. ffprobe the file. If each speaker landed on a separate channel, split them and transcribe independently — that gives perfect speaker attribution and skips diarization entirely.
  3. Convert. ffmpeg -i in.m4a -ar 16000 -ac 1 -c:a pcm_s16le out.wav. No denoising, no filters.
  4. Transcribe with large-v3-turbo, VAD on, condition_on_previous_text=False. Expect roughly three minutes for ninety minutes of audio.
  5. Diarize to separate the two voices, then review the speaker labels — overlapping speech and backchannel are where diarization actually fails, not steady two-person conversation.
  6. Scrub, review by hand, and only then paste into Claude.

One decision still open

noScribe (GPL-3.0, v0.7.2) is a Windows GUI bundling faster-whisper and pyannote with no Hugging Face account required — lowest risk for a single recording. Scripted WhisperX is reusable for every future meeting but needs an HF account and acceptance of gated model terms. WhisperX is healthy: the Blackwell issue everyone cites was closed in August 2025, and v3.8.6 shipped May 2026.

PHI scrub

Missing one is the dangerous error

Recall matters more than precision here, which is why the de-identification field scores with F2 — weighting recall twice precision. Layer three detectors, take the union of what they flag rather than the intersection, and confirm every span by hand.

  • Regex for the structurally obvious: SSN, phone, email, URL, IP, dates.
  • Presidio analyzer — note it moved from Microsoft to data-privacy-stack/presidio and is actively maintained. Use the analyzer to flag, not the anonymizer to silently redact, and add custom recognizers for medical record numbers, account numbers and device serials, which it misses by default.
  • A local LLM pass via Ollama, prompted to flag candidates only.
  • Human confirmation of every span in context. This is the safety-critical control point. Default to redacting anything ambiguous.

Still unverified

Known unknowns, recorded so they are not mistaken for facts

  • Every WER and latency figure for models other than the one benchmarked here. No published numbers exist for any RTX 50-series card.
  • Whether large-v3-turbo inherits large-v3’s hallucination regression. Worth spot-checking on the real recording.
  • Whether noScribe truly needs no Hugging Face token, or just hides the handshake on first run.
  • Whether loudness normalization before ASR helps or hurts. Denoising is confirmed harmful; loudnorm has never been benchmarked.
  • Whether any shipping Parakeet runtime exposes vocabulary biasing. Absence of evidence, not evidence of absence.
  • The exact default value of LowLevelHooksTimeout. Microsoft documents the 1000ms ceiling but not the unset default.

The faster-whisper wrapper itself was last pushed 19 November 2025 — ten months stale, while its CTranslate2 engine ships monthly. It works today and is pinned here deliberately, but it is the component most likely to need replacing.
